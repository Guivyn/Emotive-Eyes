# 连续动画 60fps：80MHz 短测记录

> 历史验证记录 · 2026-10-09。本报告中的 80MHz 临时性能环境已撤销；以下结果仅适用于报告中的短时连续负载，不代表当前 2.0.0 的循环测试固件（240MHz）。当前正式配置见[技术文档](../技术文档.md)。

## 测试条件

- PlatformIO 环境：`esp32dev_always_on_perf60_continuous_80mhz`
- 硬件：ESP32-D0WD-V3 / HW-950 ESP32-2432S024R，COM7
- 屏幕 SPI：80MHz；帧间隔：16ms；每 450ms 切换表情，循环 8 种表情
- 编译与烧录：成功；固件哈希校验通过
- 启动串口日志确认：`[POWER] cpu=80MHz`
- 串口观察约 50 秒；本次没有测量电池电流

## 结果

启动绘制窗口的平均绘制耗时为 4.657ms，最大 21.427ms，有 1 帧超过 16ms；主循环约 61.2fps，晚帧为 0。该窗口包含首次全屏绘制。

后续 11 个约 5 秒稳态绘制窗口：

| 指标 | 观测值 |
|---|---:|
| 绘制频率 | 61.1–61.4fps |
| 平均绘制耗时 | 4.645–5.117ms |
| 稳态最大绘制耗时 | 7.415ms |
| 超过 16ms 的绘制帧 | 0 |
| 主循环频率 | 约 61.2–61.5fps |
| 主循环最大间隔 / 晚帧 | 17ms / 0 |
| 运行堆内存 | 249,016 bytes，观察期间保持不变 |
| 芯片温度 | 32.2–32.8°C |
| 运行中重启 | 未观察到 |

## 结论与边界

CPU 实际为 80MHz 时，连续动画短测仍达到当前约 60fps 的程序帧率目标。相较先前 160MHz 短测，单帧绘制耗时增加，但稳态仍未超过 16ms 预算。

本次没有串联电流表或其他电流测量，因此不能据此量化整机耗电下降幅度。降低 CPU 主频会减少处理器时钟活动，但屏幕、背光和其他板载电路仍在工作；整机续航差异需要在拔掉 USB、使用同一块电池和相同亮度条件下实测。测试时间也不足以验证长时间稳定性。
