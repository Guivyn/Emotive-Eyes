# HW-950 电池供电诊断（2026-09-08）

## 已确认的连接与未确认的参数

依据本仓库 `case/esp32开发板说明书.doc` 原始文本和内嵌功能图（该文件实际为 RTF）：

- 电池接专用 BAT+/BAT− 端子；USB Type-C 支持供电、烧录及给电池充电。
- SW1 是独立电池供电键：单击开启、双击关闭；不是 ESP32 的 BOOT 或 RST。
- BOOT 接 GPIO0；RST 复位 ESP32。电源输出已关闭时，RST 不能重新开启上游电源。
- GPIO35 是扩展接口 ADC1_CH7，GPIO34 接光敏电阻；图中未标出电池采样到 ADC 的连接。
- 功能图含电池旁的电源芯片及电感，但只有封装信息，没有芯片型号或原理图。不能把 HW-950 直接当成任意 CYD 板，也不能认定安装了 IP5306。

供电功能关系为：USB → 板载电源/充电电路 ↔ BAT 端子；电池 → 板载电源转换/稳压 → ESP32 与屏幕。具体电源路径、充电终止电压及充电电流仍需原理图或实测确认。

说明书原文写“电池低于3.7V时才会充电，最高充至3.7V”。这里只记录原文，不据此设定满电阈值，也不据此修改充电硬件；需要对照实际电池化学体系、标签和充电芯片确认。

## 长时间关机后 RST 无效

旧代码在 BOOT 长按后调用 `esp_deep_sleep_start()`。深睡大幅降低 MCU 负载。如果电源芯片具有轻载关闭功能，可能在延时后关闭输出，此时 BOOT 和 RST 都不能重新供电。该解释与用户描述相符，尚未通过电池独立供电、电压测量证明。

英集芯 IP5306 的资料可作为“此类芯片确实存在自动轻载休眠”的机制参考，不能作为本板芯片型号的证据。电池低电压、保护板动作和线路接触不良仍需排除。

本次固件将手动长按改为低功耗 `SOFT_OFF`：

- BOOT 配置为 `INPUT_PULLUP` 并读取。运行状态下，去抖后的长按事件进入 `SOFT_OFF`；SOFT_OFF 状态下忽略 BOOT，只能按硬件 RST/EN 复位重新启动。按 RST 时不要同时按住 BOOT，否则可能进入下载模式。
- 背光 PWM 立即归零、显示控制器进入 Sleep-In、SPI/SD/音频/指示灯引脚固定到低泄漏状态，停止动画和触摸轮询。
- ESP32 进入 Deep Sleep，不配置 GPIO0/BOOT 或定时器唤醒；不再测温、不轮询串口。硬件 RST/EN 复位是唯一的按键开机路径。
- 这是最低 MCU 功耗的待验证方案，预计比原来 240MHz 忙等明显省电；由于负载更低，可能更容易触发未知电源芯片的低负载关断。长期不用请通过 SW1 关闭电池输出。
- 5 分钟无交互的自动 `SLEEP` 仍保持原逻辑，80MHz、黑屏、触摸唤醒；它也需在纯电池条件下观察是否触发电源关断。

## 电压诊断与采样准备

115200 波特率、换行结尾，发布固件也接受：

| 命令 | 行为 |
|---|---|
| `power` | 输出运行时间、复位原因、唤醒原因、CPU 频率和手动待机状态；默认电池电压为 UNAVAILABLE |
| `power-scan` | 额外读取 GPIO35/39 的 ADC 引脚毫伏值，扫描 GPIO21/22 的 I²C 地址应答；不写电源寄存器 |
| `off` | 进入低功耗黑屏待机 |
| `wake` | 仅在尚未进入 Deep Sleep 前恢复运行；Deep Sleep 后无效，必须按 RST/EN |

GPIO35/39 的诊断值均标为 `UNVERIFIED_INPUT_NOT_BATTERY`。悬空输入、偏置或其他板载连接都可能产生看似稳定的数值。I²C 地址应答也不能单独确认芯片身份。扫描只在明确命令时执行，不拖慢开机。

若最终确认板上没有电池采样线，需要实际添加采样硬件，软件无法凭空读出电池电压。对于已经确认是单节、最高 4.2V 的锂电池，可采用以下候选接法，施工前必须确认电池类型、极性、共地与 GPIO35 未被占用：

```text
受保护电池输出 BAT+ ── 100kΩ (1%) ──┬── GPIO35
                                 ├── 100nF ── GND
                                 └── 100kΩ (1%) ── GND
```

只测分压中点：最高约 2.1V；BAT− 与板卡 GND 共地。不能把电池正极直接接 ESP32 GPIO，也不能用稳压后的 3.3V 或升压后的 5V 推算电量。若 MCU 断电而电池仍接在分压器上，需设计可断开的采样通路/隔离，防止 ADC 反向供电；此图不是包含所有电源状态的最终电路。

确认实物分压与万用表读数一致后，才可烧录 `esp32dev_battery_divider` 环境。当前已烧录的是默认 `esp32dev`，没有启用该假定接线。

启用后：GPIO35 设置 11dB 衰减，丢弃首次转换，再平均 32 次 `analogReadMilliVolts()`；电池电压 = 引脚毫伏 × 2 / 1000。ADC 值超出 150–2450mV 时返回 INVALID。区间检查不能证明接线正确，必须先完成实物检查及万用表校准。固件不输出电量百分比或充电状态；电压无法独立证明正在充电。

## 本次真实验证

- 当前连接：USB-SERIAL CH340，COM8（不是历史记录的 COM7）。
- 烧录识别：ESP32-D0WD-V3 revision v3.1，eFuse 含 VRef 校准。
- `pio test -e native`：13/13 通过，含松手触发、去抖、持续按住不重复触发和毫秒计时回绕。
- `pio run -e esp32dev_battery_divider`：条件采样分支编译通过，仅验证可构建，未烧录、未验证实物电压。
- `pio run -e esp32dev`：成功，RAM 22940 bytes，Flash 430533 bytes。
- `pio run -e esp32dev -t upload --upload-port COM8`：成功，固件 Hash 校验通过。
- USB 连接下两次 `power-scan`：GPIO35 为 142mV；GPIO39 为 1185、1169mV；I²C 设备数 0、总线错误数 0。没有发现可用电量接口；不能由此证明未暴露的线路不存在。
- 旧版串口 `off` 后运行时间 52190ms、63151ms 均报告 `SOFT_OFF`、240MHz；`wake` 后 68281ms 报告 `RUNNING`。这是旧版忙等待机的证据。Deep Sleep 版本已重新在 COM8 烧录，ESP32-D0WD-V3 识别正常，全部分段均报告 `Hash of data verified.`；尚未用电流表测得实际电流。
- 当前测试结束后已恢复运行。临时提取图文与原始串口记录在 `.pio/power-audit/`，该目录受 Git 忽略，清理构建缓存可能删除它。

## 必须由实物完成的下一步

1. 拔 USB，仅用电池；通过串口 `off` 进入待机，等待超过原失效时长，再按 RST（不要按住 BOOT）。
2. 失败时单击 SW1。如果恢复，进一步测失效前后的 BAT、板上 5V 和 3.3V，区分上游电源关闭与 MCU 问题。
3. 若 BAT 仍有正常电压但电源轨消失，确认电源芯片丝印，再选择其有文档支持的常开模式或适合微功耗负载的电源模块；不盲写寄存器、不旁路电池保护。
4. 若 BAT 本身明显下降或保护板断开，检查电量、接插件和保护板。充电电压与电池类型也需实测核对。
