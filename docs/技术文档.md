# ESP32 Emotive Eyes — 技术文档

> 对应固件版本：**2.0.0**。当前固件环境和参数以根目录 `platformio.ini`、`src/Config.h`、`src/PowerManager.cpp` 为准；历史测量不代表当前环境的长期表现。

## 概述

ESP32 + ST7796 TFT（逻辑分辨率 320×240）过程式生成的表情眼睛系统。眼睛几何由 CPU 实时计算，无需预渲染资源文件。当前提供 `esp32dev_always_on`、`esp32dev_battery` 和 `esp32dev_expression_test` 三种构建环境。

核心算法移植自 Alastair Aitchison / playfultechnology 的 SH1106 OLED 版本，渲染方式改为基于浮点贝塞尔边界 + 扫描线填充的过程式管线。

## 硬件要求

| 组件 | 型号 |
|------|------|
| MCU | ESP32（ESP32-WROOM-32 系列） |
| 屏幕 | ST7796 SPI TFT (320×240) |
| 驱动库 | TFT_eSPI（通过 platformio.ini 构建开关配置） |
| 背光控制 | GPIO 27（低电平关，高电平开） |

### TFT_eSPI 配置要点

无需修改 `User_Setup.h`。本项目通过 `USER_SETUP_LOADED=1` 在
`platformio.ini` 的 `build_flags` 中直接配置：

- `ST7796_DRIVER`
- `TFT_CS`、`TFT_DC`、`TFT_RST`、`TFT_BL` 等引脚
- `SPI_FREQUENCY=80000000`（80MHz）
- `TFT_RGB_ORDER=TFT_BGR`

main.cpp 中仅调用 `tft.begin()`。

## 系统架构

### 渲染管线

每帧 Eye::Update() 按序执行以下 5 级变换，输出链式传递：

```
Transition → Transformation → Variation1 → Variation2 → Blink → FinalConfig
```

```
                   ┌──────────────────┐
  Transition ─────→│  Transition.Output│←──── Snapshot（转换起点）
                   └────────┬─────────┘
                            ↓
                   ┌──────────────────┐
  Transformation ─→│Transformation.Out│←── Destin（视线目标 + Scale）
                   └────────┬─────────┘
                            ↓
                   ┌──────────────────┐
  Variation1 ─────→│ Variation1.Output │←── Values（微表情参数）
                   └────────┬─────────┘
                            ↓
                   ┌──────────────────┐
  Variation2 ─────→│ Variation2.Output │←── Values（微表情参数）
                   └────────┬─────────┘
                            ↓
                   ┌──────────────────┐
  Blink ──────────→│  Blink.Output     │←── 眨眼（压缩高度 + 拉伸宽度）
                   └────────┬─────────┘
                            ↓
                    FinalConfig → EyeDrawer::Draw()
```

### 动画引擎

所有动画均继承自 AnimationBase，以 millis() 为时间基准，帧率无感知。

| 类 | 波形 | 用途 |
|----|------|------|
| RampAnimation | 0 → 1（Smoothstep：t²(3−2t)，保持） | Transition、Transformation |
| TrapeziumAnimation | 0 → 1 → 0（梯形，单次） | 眨眼 |
| TrapeziumPulseAnimation | 0 → 1 → hold → 0 → hold（循环脉冲） | Variation 脉冲 |

### 状态组件

#### EyeTransition — 表情切换

当表情切换时：
1. TransitionTo() 将当前 Transition.Output 快照到 Snapshot
2. 设置 Destin 为目标表情配置
3. 启动 RampAnimation(500ms)，使用 Smoothstep 从 Snapshot → Destin 插值

所有几何字段（Offset、Height、Width、Slope、Radius）均参与插值。

关键：使用 Snapshot 作为固定起点，而非原地修改 Config（避免帧率依赖漂移）。

#### EyeTransformation — 视线方向

LookAssistant 以 1.5–3.5 秒为基础等待区间，并根据当前表情缩放事件间隔。移动目标由当前注视方向和少量随机扰动共同生成，让小幅漂移保留连续性；偶尔执行较大范围的扫视，并安排回中或快速微调。

- MoveX = -20 × x（左右偏移）
- MoveY = 20 × y（上下偏移）
- ScaleY = max(0.90, 1 - 0.05×|x| - 0.08×|y|)（轻微纵向透视缩放）
- ScaleX = 1.0（不缩放宽度）

每次 `SetDestin()` 将当前 Output 保存到 Origin，再从 Origin 平滑过渡到新 Destin。不同动作采用不同持续时间：微动约 240–360ms；较大扫视约 110–170ms；回中约 140–200ms；偶发微调约 200–280ms。

如果眼睛正在眨眼或表情过渡，新的眼神事件会短暂推迟；扫视后停留约 700–1600ms 再回中。微动或扫视的概率、幅度和等待时间按表情调整：

| 表情 | 间隔倍率 | 移动倍率 | 较大扫视概率 |
|---|---:|---:|---:|
| Sleepy | 1.80 | 0.45 | 3% |
| Sad | 1.45 | 0.70 | 7% |
| Unimpressed | 1.60 | 0.60 | 5% |
| Focused / Squint | 1.25 | 0.75 | 8% |
| Happy / Glee / Coquette | 0.70 | 1.10 | 28% |
| Surprised / Scared / Awe | 0.62 | 1.05 | 35% |
| Worried / Suspicious / Skeptic | 0.82 | 0.95 | 26% |
| Angry / Furious | 0.95 | 0.82 | 20% |
| Annoyed / Frustrated | 0.90 | 0.68 | 12% |
| Normal | 1.00 | 1.00 | 15% |

Origin 快照确保新视线动作从当前画面继续，不会跳回 OffsetX=0 的中间位置。

#### EyeVariation — 微表情

每个表情可设置 Variation Values（如 Normal 眼高偏移 2–3 像素、宽度偏移 1–2 像素），通过 TrapeziumPulseAnimation 产生呼吸/脉冲效果。

当表情切换时，StartFadeOut() 捕获当前实际偏移量到 FadeValues，在 150ms 内渐出至零，避免"闪回"。

#### EyeBlink — 眨眼

BlinkAssistant 每 2~5 秒触发一次眨眼。TrapeziumAnimation(100ms→50ms→100ms) 将眼睛高度压缩至接近零再恢复。

### 表情系统

19 种预设表情，每种定义完整的 EyeConfig：

| 表情 | 特征参数 |
|------|---------|
| Normal | Height=60, Width=60, Radius_Top/Bottom=12 |
| Angry | Height=30, Width=60, Slope_Top=0.3, Radius_Bottom=18 |
| Happy | Height=14, Width=60, Radius_Top=14 |
| Sad | Height=23, Width=60, Slope_Top=-0.5, Radius_Bottom=14 |
| Surprised | Height=67, Width=67, Radius_Top/Bottom=24 |
| Sleepy | Height=22, Width=60, Slope_Top/Bottom=-0.5 |

每种表情还可附带 Variation 参数使眼睛产生自然微动。

当前 Face 的基准 EyeSize 为 70，眼间距参数 `EyeInterDistance` 为 15；Normal 预设的每只眼睛宽、高均为 60 像素。

### 行为系统

#### 启动阶段

| 时间 | 事件 |
|------|------|
| 0ms | Face 创建并直接显示闭眼画面 |
| 500ms | 显示 Normal 表情 |
| 5000ms | 开启随机视线（LookAssistant） |
| 8000ms | 开启随机眨眼 + 随机表情切换 |

#### 表情权重

FaceBehavior 以权重随机选择下一个表情：

| 表情 | 权重 |
|------|------|
| Normal | 4 |
| Angry / Glee / Happy / Surprised | 2 |
| 其余 | 1（Sleepy 为 2） |

随机表情定时器周期 6 秒，Transition 动画 500ms；抽到不同表情时，表情过渡后至少停留约 5.5 秒，抽到当前表情则本轮不切换。

LookAssistant 将较小的注视漂移与较快的扫视分开处理，并在扫视后安排回中或短暂微调。速度、幅度和扫视概率随当前表情调整；眨眼或表情过渡期间会暂缓新的眼神移动。

### 几何渲染：EyeDrawer

EyeDrawer::GenerateBoundary() 根据 EyeConfig 生成眼睛边界多边形：

1. 计算 4 个内角坐标（TL/TR/BL/BR），考虑 Slope 引起的偏移
2. 在 4 个角位置产生圆弧段（每 15° 一个采样点），共约 24+ 个边界点
3. 如果圆角半径超过眼睛总高度，按比例缩小

EyeDrawer::RasterizePolygon() 使用 8 个垂直采样点估算每行各像素的边缘覆盖率，再将覆盖值混合到眼睛颜色中。眼睛轮廓为凸多边形时，扫描器沿顶点两侧的单调边链增量维护左右交点，避免每个采样行重新计算和排序所有交点；非凸或特殊轮廓回退到通用 even-odd 扫描路径。内部完整覆盖区域仍按水平跨度快速填充。

渲染器优先申请一块 TFT_eSprite 全屏缓冲（320×240，约 150KB），每帧将两只眼睛和睡眠符号完整绘制后一次性推送。对于没有足够连续 RAM 的 ESP32，自动退回一个 160×240 全高分块并分两次推送左右半屏；每个分块都覆盖完整背景和场景，因此不会因缓冲申请失败而白屏，也不会留下局部旧帧。

## 触控交互

板载 XPT2046 触摸屏与 TFT 共用同一 SPI 总线，仅片选独立。实际接线经启动扫描确认：

| 信号 | GPIO | 备注 |
|------|------|------|
| TOUCH_CS   | GPIO33 | 片选 |
| TOUCH_CLK  | GPIO14 | 与 TFT_SCLK 共用 |
| TOUCH_MOSI | GPIO13 | 与 TFT_MOSI 共用 |
| TOUCH_MISO | GPIO12 | 与 TFT_MISO 共用 |

驱动使用 TFT_eSPI 内置 XPT2046 读取（`TOUCH_CS` + 共享 SPI），按 Z 轴压力判断按下，不依赖 IRQ 引脚。引脚定义写入 `platformio.ini` 的 `build_flags`，方便按实际接线调整。

### 连续点按 → 愤怒表情

默认配置下：

1. 每次按下并松开登记一次点按；1.5 秒无新点按会清空计数。
2. 第二次点按启动 300ms 确认窗口；窗口到期仍只有两次时回到 Normal。
3. 在确认窗口到期前完成第三次点按会触发 Angry。

按下压力阈值默认 `TOUCH_PRESSURE_THRESHOLD = 600`，松开迟滞阈值为 400；按下和松开均需连续 2 次采样确认，以抑制压力尖峰和阈值抖动。不同面板可根据空闲与按压时的压力读数微调；每个点按需完成一次按下→松开，长按不会重复计数。

## 电源管理（2.0.0）

提供常亮与分级省电策略，减少空闲时的亮度和绘制负载。电池容量及板上具体供电路径需以实际电池标注和测量为准；当前实现的软件策略由 `platformio.ini` 的构建环境控制。

### 运行状态

| 状态 | 进入条件（距上次交互） | 背光 | 程序间隔 / 目标节奏 | 表情行为 |
|------|------------------------|------|--------|----------|
| ACTIVE | 0–60 秒 | 用户亮度 | 16ms（约60fps目标） | 完整动画、眼神和随机表情 |
| RELAX | 60秒–3分钟 | 用户亮度的50% | 22ms（约45fps目标） | 固定表情、慢速视线、随机眨眼和偶发哈欠 |
| IDLE | 3–5分钟 | 用户亮度的25%，最低20% | 33ms（约30fps目标） | 固定 Normal，关闭随机表情、视线和眨眼 |
| SLEEP | 5分钟起 | 0% | 停止绘制；每50ms触摸轮询 | Sleepy 闭眼静态画面 |

在 SLEEP 状态触摸会唤醒设备并返回 ACTIVE；SOFT_OFF 不轮询触摸，也没有触摸唤醒源。
电池固件的 CPU 频率随状态调整：ACTIVE 80MHz、RELAX 80MHz、IDLE 40MHz、SLEEP 80MHz。`esp32dev_always_on` 默认保持 ACTIVE 档；`esp32dev_expression_test` 将 ACTIVE CPU 设为 240MHz。16/22/33ms 是程序调度间隔，不是面板物理刷新测量。自动省电状态表只作用于 `esp32dev_battery`；常亮固件仍支持温度保护、手动下滑睡眠和 BOOT 软件关机。

循环表情测试固件关闭随机视线、随机眨眼和随机情绪选择，按固定的 8 种表情序列做持续绘制；生产运行时的随机视线策略见 EyeTransformation 小节。

手动下滑先显示 Sleepy 并在约 2 秒内把背光渐变至 IDLE 档，随后进入 IDLE；它不是自动 SLEEP。BOOT 按住约 1 秒并松开进入 `SOFT_OFF`：关闭背光和显示控制器后进入 Deep Sleep，不配置 GPIO/定时唤醒；RST/EN 复位后重新启动。物理切断电池输出仍需使用板载 SW1。

用户亮度范围为 20–100%，默认 100%，并保存在 NVS。左右滑动每次调整 10%；串口 `brightness` 查询，`brightness <20-100>` 修改。ACTIVE 使用用户亮度，RELAX/IDLE 目标分别为用户亮度的 50%/25%，最低为 20%；SLEEP 和 SOFT_OFF 关闭背光。背光使用 Gamma 2.2 感知曲线，并按 20ms 节奏渐变到目标档位。

渲染采用事件驱动：`Face::Update()` 通过 `Eye::NeedsRedraw()` 判断眨眼、表情切换、视线、微表情等动画是否在变化，只有画面变化时才推 sprite；RELAX/IDLE 进入时清除呼吸微表情，静止期间 SPI 不工作。

自动调光和电池/充电检测均已移除。该板光敏硬件接在 GPIO34，但动态范围偏窄、易误调暗，暂不使用。

### 触摸手势

| 手势 | 动作 |
|------|------|
| 单击 | 眼睛快速眨眼作为反馈，并重置空闲计时 |
| 双击 | 触发 300ms 确认窗口后回到 Normal 表情 |
| 三连击（第三次需在二连击的300ms确认窗内完成） | 触发 Angry 表情 |
| 长按（2s） | 回到 Normal 表情 |
| 上滑 | 撒娇（Coquette） |
| 连续上滑两次（700ms 内） | 庆祝连招：Glee → Awe → Happy，结束后回到 Coquette |
| 左滑 / 右滑 | 亮度每次降低 / 提高 10%（范围 20–100%） |
| 下滑 | 显示 Sleepy + 月牙星光标记；约 2 秒后进入低功耗 IDLE，再次触摸唤醒 |

### 温度保护与统计

- `POWER_TEMP_PROTECT_ENABLED=1`：芯片温度 ≥70°C 强制降入 IDLE，≥80°C 强制 SLEEP，每 5 秒采样一次；
- 每 30 秒串口输出 `[STATS]`：当前状态、背光档位、帧间隔、芯片温度；
- RELAX 状态下约每 20–60 秒随机打一次“哈欠”（短暂 Sleepy 后回 Normal）；
- 开机直接显示闭眼，约 500ms 后睁眼醒来的过渡；
- 主循环日志改为每 5 秒一次，不再随帧数输出。

### 模块与构建开关

| 文件 | 职责 |
|------|------|
| `src/PowerManager.h/.cpp` | 状态机、背光 PWM、温度保护、LightSleep 入口 |
| `src/FacePower.h` | 表情层与电源层之间的解耦接口 |

校准文件采用 `CalibrationCodec::Record`（魔数、版本、offset、range、FNV-1a 校验和），写入临时文件成功后再原子替换正式文件，并兼容旧版 8 字节格式。
默认启动不会自动格式化 LittleFS；维护时可显式发送 `fs-init`，仅在普通挂载失败时格式化并重新挂载（该操作可能清除 LittleFS 内容）。

`platformio.ini` 中的开关：

| 开关 | 默认 | 说明 |
|------|------|------|
| `POWER_LIGHT_SLEEP_ENABLED` | 0 | GPIO36 触摸 IRQ 补 10kΩ 上拉后改为 1 |
| `POWER_TEMP_PROTECT_ENABLED` | 1 | 芯片温度保护 |
| `POWER_PROFILE_ALWAYS_ON` | 0 | 电池固件为 0；默认常亮固件设为 1，禁用无人触摸时的自动省电状态转换 |
| `SERIAL_DEBUG_ENABLED` | 0 | 常亮与电池固件关闭；表情测试固件开启 |

## 已知问题与修复记录

### 修复 1：白屏（Input→Output 链断裂）

Transition 完成后 Active = false，但 Transformation 仍在读取 Transition.Output。早期版本 Transformation 的 Destin 默认全零，导致输出被清零。修复：TransitionTo() 同步设置 Destin + Sync() 初始化。

### 修复 2：表情切换"闪回"

ClearVariations() 瞬间清零 Variation Values → 眼睛高度跳变。修复：StartFadeOut() 用 150ms 渐出旧偏移量。

### 修复 3：周期性"闪回中间"

早期 LookAssistant 改变视线方向时，Transformation 的 SetDestin() 未保存当前输出状态。restart 后的首帧回到 Input→OffsetX（表情默认偏移量，通常为 0），表现为眼睛"跳回中间"。修复：SetDestin() 将当前 Output 保存到 Origin，Apply 从 Origin → Destin 插值；当前视线行为与表情参数见上文。

### 修复 4：启动闪随机形状

ChainOperators() 中 Transition.Output = Config 将未初始化的 Config （堆垃圾）复制到 Transition.Output。首次 Transition 以垃圾值作 Snapshot。修复：删除该行，Transition.Output 从全零开始。

## 编译与烧录

### 前置条件

1. 安装 [PlatformIO](https://platformio.org/)（VS Code 扩展 或 CLI）
2. 安装 TFT_eSPI 库（platformio.ini 中已配置 lib_deps）

### 编译

`pio run` 默认编译常亮固件 `esp32dev_always_on`。另外两个保留环境为 `esp32dev_battery` 和 `esp32dev_expression_test`。

```bash
pio run
```

```bash
pio run --target upload
```

pio test -e native

## 2026-09-08 电池诊断与手动待机更新

开机状态下长按 BOOT 约 1 秒并松手进入 `SOFT_OFF`；PWM 背光立即归零，ST7796 进入 Sleep-In，SPI/SD/音频/指示灯相关引脚固定到低泄漏状态，ESP32 随后进入 Deep Sleep，不配置 GPIO0 或定时器唤醒。关机状态下 BOOT 输入被忽略，只能按硬件 RST/EN 复位并重新启动。若按 RST 时同时按住 BOOT，GPIO0 可能使 ESP32 进入下载模式；长期不用仍应使用板载 SW1 关闭电池输出。

新增 `power`、`power-scan`、`off`、`wake` 串口命令；`wake` 仅在尚未进入 Deep Sleep 前有效，Deep Sleep 后必须按 RST/EN。默认不启用电池测量，GPIO35/39 探测输出仅代表引脚电压。详细硬件依据及验证记录见 [电池供电诊断](电池供电诊断.md)。
